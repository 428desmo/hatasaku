# はたさく Web Lite · Garden UX 仕様 v1.2

更新日：2026-10-21。参照ルール：`hatasaku_rules_v0.17.md`。
本書は Web Lite 初版の画面・演出仕様を置き換える。ゲームルールと既存 `src/` は変更しない。

## 体験の方針

「一手、ひと畑。」をテーマに、絵本のような田園と、触って動かす作物カードで遊ぶ。
スマートフォンの横向きが主対象。基準844×390、667×375から932×430の横画面とデスクトップを確認する。
縦向きにも同じURLで対応する。向きを変えても対局・選択・演出を維持する。画面の強制回転や全画面表示は要求しない。

人間1人＋CPU、合計3〜5人。基本10R／上級18R。シーズン数は人数と同じ、または1。
既存エンジンとirr戦略を使い、初期コイン、農地上限、競合、天候、呪い、手番順、勝敗はルールどおり。
オンライン・複数端末・複数人の人間には対応しない。

## 盤面

- 上：ブランド、シーズン、ラウンドの進行目盛り、BGM切替、遊び方、設定。
- 左：全員の畑は自分を最下段、他プレイヤーを手番順で固定表示。表示位置と手番順は分離し、番号で実際の手番順を示す。プレイヤーの顔・順番・所持コイン・全農地を常時確認できる。
- 右上：今・継続・2R先までの天候カード。期間は最終ラウンドで切る。詳細はタップ。
- 右下：フル情報の場札。3〜4人で3枚、5人で4枚を横並び。作物名は省略しない。
- 下：現在の一手、学習ヒントまたは前Rの収穫、パス・呪い・演出操作。

横画面のゲーム中はページ全体をスクロールさせない。端末のsafe areaと動的な画面の高さを考慮する。
基本5農地／上級6農地を各プレイヤー1行で表示。
作物名は農場では3文字以内の略称。原画を使った小さな作物イラスト、基本／最低、現在の段階だけを載せる。
待機は○、収穫は✦、連作休みは▽。空き・未取得・休耕は破線。休耕には収入や将来の段階を載せない。
ミニカードのタップでフル情報と説明を確認できる。CPU演出中に開いた場合も、その間は進行を止める。

フル場札には栽培費、待機R、収穫R、基本／最低保証、連作休みを文字と数字で表示。
狭い画面で4枚ある場合は、栽培費と作物名を上下に分けて重なりを避ける。
野菜のイラストは専用の領域内に収めて上寄せし、下に余白を確保する。ゴボウなど縦長の絵も待機R・数値に重ならないよう、領域外をクリップする。
型名は印刷せず、紹介時のコメントで性格を伝える。植え付けできないカードは無効・グレーアウト。

今季の4種は場札の上のイラストボタンから再確認できる。カード別の説明はモーダルにまとめる。
呪いは天候列に押し込まず、枚数・伏せ状態・使用者を示すボタンから詳細を確認する。
伏せ中の他人の対象は隠す。本人の選択した対象、既に公開された対象は確認できる。
次の呪いを選ぶ人は使用済み対象も確認できる。使用後も通常の一手は残る。
権利は👿、前シーズンまでの累計首位は👑。手番の🖐️は使わない。

## スマートフォン縦画面

幅700px以下の縦向きでは盤面を「全員の畑 → 天候 → 場札」の1列に再構成する。
全員の所持コイン・全農地・現在の段階を残し、プレイヤーの顔は省く。農地は基本5／上級6列を維持。
場札は2列で、横長の小さなカードにする。絵と栽培費、待機・収穫・基本／最低・休みの全情報を残す。
場札のピップ・印刷番号・各カードの操作説明は省き、数値と文字で読む。今季の作物、天候・呪い詳細は従来どおりタップで開く。
下部の操作エリアを固定し、手番・学習ヒント・パス・取り消し・収穫操作に常時アクセス可能にする。
iPhoneのsafe area・ブラウザUIを除いた実際の盤面の高さをコンテナクエリで判定し、農場行38〜51px・天候65〜76px・場札101〜104pxに調整する。操作欄の最低高は70px。5人戦の4枚目まで表示できるよう余白を削り、文字情報は維持する。極端に短い端末では盤面内を縦スクロール可能。種を選んだ時は合法な自分の農地を画面内に戻す。
紹介は4種類を2×2、振り返りは得点を2列＋行動表の横スクロール、グラフは凡例を上に置く。
タイトル、詳細、設定、表彰も1列中心の構成にする。BGM・SE・絵・演出速度・ルールは横画面と共通。

## 植える・考える

場札をタップ → 合法な自分の農地だけが光る → 農地をタップして確定。
選べない農地は他人の農地を含め薄くする。取り消しは「やめる」。確認ボタンを増やさない。
キーボード操作では、場札選択後に最初の候補農地へフォーカスを移す。Escapeで選択解除。
植え付けは種の移動と葉の効果音、支払いで伝える。ルール処理は選択した一手につき1回だけ。

学習ヒントONなら、選択した作物の収穫可能R・回数・公開済みのイベントの影響を下部に表示。
未公開の山札や、見る権利のない呪いは参照しない。競合や将来のイベントで変動することを添える。

## テンポと割り込み

標準テンポのCPUの植え付け：手番95ms → 場札100ms → 農地105ms → 支払い100ms。
パス／呪いは短くする。呪い後は同じプレイヤーの通常の一手が続く。
演出中のプレイヤーは表示上も最後まで本人を強調してから次へ移す。

設定で「ゆったり×1.5／ふつう×1／快速×0.55」を選べる。
早送りは上部ツールバーの専用位置に常設し、演出中だけ有効にする。下部のパスとは位置を分け、連打でパスを誤操作しないようにする。
「演出を省略」またはSpaceで進行中の演出をまとめる。ゲーム状態を飛ばしたり、処理を重複させたりしない。
設定、ルール、カード詳細、内訳を開いた間や、タブが非表示の間は、次の演出境界で待つ。
明示的な一時停止もできる。対局終了・再開始時は進行中の待ちを取り消す。
OSの視差効果軽減設定では移動・点滅を止め、演出待ちも短くする。

## 収穫：確認待ちから、流れの中のご褒美へ

デフォルトで自動進行する。毎ラウンドの「次へ」は要求しない。
収穫は農地を1個ずつ巡らず、プレイヤー単位の短い波で進める。

1. 下部に「実りの時間」と今回の全体収穫高を表示。220ms。
2. 手番順に、各プレイヤーの全農地の結果を同時に表示。90ms／収穫のあるプレイヤー。
3. 各農地からコインが財布へ飛び、財布とプレイヤー別合計を更新。
4. 収穫をエンジンに1回だけ確定し、呪いを公開。400msで結果を見せて次Rへ。

標準演出は最大5人で約1.07秒。農地が30あっても待ち時間を増やさない。
収穫ゼロなら「まだ、育ちざかり。」と示し、180msで次へ進む。
次Rの最初がCPUなら、そのままCPUの手番へ。人間の一手では必ず入力を待つ。
最終Rは自動でシーズンの振り返りへ移る。

途中で「結果を見る」を押すと、その回だけ集計後に停止。設定で自動進行をOFFにもできる。
停止時は全農地の収入、全員の収穫合計と「次のラウンドへ」を表示。

自動進行後も「前Rの収穫」から内訳を再表示できる。
内訳には作物・農地・基本・天候・競合・最低保証・実際の収入を掲載する。
前Rの履歴は新シーズンで消す。公開済み呪いの詳細は、使用者と有効Rを示す。

## 紹介・振り返り・表彰

シーズン開始時だけ、今季4種をイラスト入りフルカード＋コメントで紹介。
手番順と初期コイン、呪いの権利も確認し、「シーズンをはじめる」で開始。

シーズン終了後：
1. 個人別のシーズン得点→累計、作物イラストと略称によるラウンド別行動表。
2. 作物／パスの比率を示す帯グラフ。
3. 次シーズン、または最終の得点推移。

最多得点は太字＋✌️。最少は😱（全員同点は付けない）。同率は全員を対象にする。
行動表は列を45msずつずらして出す。狭い画面は表内だけをスクロールできる。

最終グラフは各シーズン終了時の累計の、その時点のプレイヤー間の偏差値をY位置にする。
縦軸の数値や単位は表示しない。頂点は実際の累計得点。
その後、同率を含む総合順位と優勝者を田園の表彰画面に表示。
「もうひと畑、同じ設定で」は新しいseedの対局を開始する。

## グラフィックと音

`art.ts` に野菜14種、5人の農夫、田園風景、操作アイコンのオリジナルSVGを収録。
外部画像・Webフォントを取得しない。イラストの色と作物の種類を対応させる。
アニメーションは主に移動・透明度を使い、ゲーム本体のDOMは変更した区画だけを更新する。

`audio.ts` はWeb AudioでオリジナルのBGMとSEを生成する。
BGMは88BPM、4つの和音とペンタトニック系の短いフレーズ、柔らかい低音のループ。
SEは選択、植え付け、コイン、パス、呪い、開始、手番、表彰。
BGMとSEのON/OFFは独立して保存する。音量は控えめで、マスターにコンプレッサーを置く。
開始や再開などのユーザー操作の後にだけ音声を有効化。自動再生に失敗しても対局は続行する。
タブを離れたら音を止め、戻った時に再開を試みる。多重スケジューラを作らない。
音声ファイルの読み込みはない。

## 保存と構成

同じ端末・同じブラウザ内で自動保存。タイトルに「つづきから」を表示。
seed・設定と成功したルール操作の履歴をlocalStorageへ保存し、既存エンジンで再生して復元する。
収穫前／後を区別し、再読込時に二重加算しない。シーズン間も同じ乱数の続きへ戻る。
完了したマッチは再開候補から除外。壊れた保存・非対応の版は無視して新規対局を可能にする。
保存できない環境では、画面内に通知してその場の対局を続ける。

`match.ts` はルール進行と履歴、`experience.ts` は演出の波と中断、`app.ts` は入力・画面の組み立て。
既存 `src/engine`、`src/cpu`、純粋な得点推移・見通し計算を再利用する。
配信成果物はHTML/JS/CSSの3ファイルのみ。外部ライブラリの実行時読み込み、サーバー常駐は不要。
VPSへの公開は `conoha/update.sh`。既存ゲームと共通インデックスを保持し、検査失敗時は元に戻す。
